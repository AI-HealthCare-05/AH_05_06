# 로딩 · 빈 상태 · 오류 — 같은 상황을 같은 말로

KEY-105. Sprint 2~4 에서 각자 만든 화면의 세 상태를 와이어프레임 정본과
대조하고 어긋난 곳을 맞춘 기록이다.

## 대조 결과 — 로딩과 빈 상태는 멀쩡했다

먼저 잘못 짚은 것을 적어 둔다. **처음에는 로딩 문구가 셋으로 갈렸다고 봤는데,
세어 보니 아니었다.**

```
확인 중…                        로그인 버튼 — 자격을 확인하는 중
설정 중…                        비밀번호 제출
저장 중…                        판독 값 한 칸 저장
불러오는 중…                     환자 카드 · 의사 화면 데이터
판독 중입니다                    OCR 작업 진행
차트번호가 이미 있는지 확인하는 중입니다   중복 조회
안내를 불러오는 중이에요…            환자 화면
```

**전부 「지금 무엇이 도는 중인가」를 구체적으로 말한다.** 하나로 합치면 오히려
나빠진다 — 「불러오는 중」 하나로 뭉치면 저장 중에 화면이 그렇게 떠서 무엇을
기다리는지 알 수 없다. 그대로 둔다.

빈 상태도 마찬가지다. 스물한 가지가 전부 합쇼체(`…없습니다`)로 일관되고,
「선택한 상태에 해당하는 환자가 없습니다」와 「오늘 등록된 환자가 없습니다」처럼
**왜 비었는지까지 갈라 적는다.** 손댈 곳이 없었다.

## 갈려 있던 것 — 오류 한 문장

같은 문장이 세 가지로 적혀 있었다.

| | 어미 | 뒤/후 | 마침표 |
|---|---|---|---|
| `login.js` · `password.js` | 습니다 | **후** | 없음 |
| `upload.js` | **어요** | — | 없음 |
| `patients.js` · `detail.js` | **어요** | 뒤 | 있음 |
| `doctor.js` | 습니다 | 뒤 | 있음 |
| `ocr-review.js` | 습니다 | 뒤 | 없음 |

**`login.js` 는 한 파일 안에서 「후」 셋과 「뒤」 하나를 쓰고 있었다.**
`upload.js` 도 「올릴 수 있어요」와 「올려 주세요 · 남아 있습니다」가 섞여 있었다.

## 정한 것

**어미는 화면이 누구에게 말하는가로 갈린다.**

| 화면 | 어미 | 왜 |
|---|---|---|
| `L` · `S` · `D` · `A` — 직원 | **합쇼체** | 와이어프레임 정본이 합쇼체다. 빈 상태 스물한 가지도 전부 그렇다 |
| `P` — 환자 | **해요체** | 진료실 밖에서 혼자 읽는 글이다. `guide.js` 가 이미 그렇게 쓴다 |

환자 화면의 해요체는 **고칠 어긋남이 아니라 지켜야 할 갈래다.** 「링크가
닫혔어요」를 「링크가 닫혔습니다」로 바꾸면 안내문이 통지서가 된다.

**「잠시 뒤」로 쓴다.** 와이어프레임 `L-2` 가 「잠시 뒤 다시 시도해 주세요.
(10분)」로 적어 두었다. 「후」와 「뒤」는 뜻이 같아 어느 쪽이든 되지만, 두 개를
같이 쓰면 같은 화면이 두 사람 손에서 나온 것으로 읽힌다.

**두 문장이면 각 문장에 마침표.** 한 조각짜리 이름표(빈 상태 제목 · 배지)에는
안 붙인다.

```
✅  저장하지 못했습니다. 잠시 뒤 다시 시도해 주세요.
✅  오늘 등록된 환자가 없습니다
❌  저장하지 못했어요. 잠시 후 다시 시도해 주세요
```

## 고친 곳

`develop` 에 있는 셋만 이 브랜치에서 고쳤다. 나머지 넷은 아직 열린 PR 안에
있어서 각자의 브랜치에서 맞춘다 — 여기서 고치면 병합할 때 충돌한다.

| `login.js` | develop | ✅ 「후」 3곳 → 「뒤」 · 마침표 |

## 남은 것

**잠긴 계정 문구에 남은 시간이 붙는다** — 「잠시 뒤 다시 시도해 주세요.
(10분)」. 이건 와이어프레임이 그렇게 정한 것이라 그대로 둔다. 다만 「잠시
뒤」와 「(10분)」이 같이 있으면 「잠시」가 10분이라는 뜻이 되어 어색하다는
의견이 있을 수 있다. 문구 자체를 바꾸려면 와이어프레임 `L-2` 부터 고쳐야 한다.
