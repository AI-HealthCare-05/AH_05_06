# 공통 컴포넌트와 톤 — 세 화면이 같은 것을 같게 그린다

KEY-104. 와이어프레임 셋(Admin · Medic · Patient)을 대조해 **버튼 · 입력칸 ·
카드 · 배지**가 서로 어긋나는 곳을 찾고, 실제로 나가는 CSS 를 하나의 토큰
집합으로 모은 기록이다.

정본은 두 곳이다. 어느 쪽을 보아야 하는지가 자주 헷갈려서 먼저 적는다.

| | 무엇 | 누가 고치나 |
|---|---|---|
| `docs/wireframes/*.html` | **화면이 무엇을 담는가** — 프레임 · 문구 · 흐름 | 디자인 |
| `frontend/css/tokens.css` | **그것이 어떤 값으로 그려지는가** | 구현 |

와이어프레임은 Figma 내보내기라 컴포넌트가 인라인 스타일로 흩어져 있다
(`medic` 만 4,875개). 거기를 손으로 고치면 다음 내보내기 때 지워진다. 그래서
**대조는 와이어프레임에서 하고, 정리는 `tokens.css` 에서 한다.**

## 1. 대조 결과 — 세 화면이 실제로 얼마나 다른가

인라인 스타일을 전부 긁어 값별로 셌다.

### 모서리 (`border-radius`)

| 값 | admin | medic | patient |
|---:|---:|---:|---:|
| 2px | 0 | 60 | 1 |
| 3px | 0 | 100 | 21 |
| 4px | 7 | 66 | 10 |
| 5px | 4 | 98 | 2 |
| **6px** | **58** | **424** | 0 |
| **8px** | 26 | 194 | 47 |
| 9px | 7 | 29 | 0 |
| 10px | 0 | 28 | 51 |
| **12px** | 0 | 35 | **97** |
| 13px | 0 | 4 | 0 |
| 16px | 0 | 8 | 44 |
| 999px | 0 | 80 | 0 |

**열두 가지다.** 그리고 이건 단순한 난잡함이 아니다 — `medic` 은 6px 에,
`patient` 는 12px 에 몰려 있다. **두 화면이 서로 다른 둥글기를 원한다.**
의료진 화면은 정보가 빽빽해 각지고, 환자 화면은 모바일이라 부드럽다.

그래서 「하나로 통일」은 답이 아니다. 필요한 것은 **작은 단계**다.

### 글자 크기 (`font-size`)

스물넷이 나왔다. 그중 `10.5px` · `11.5px` · `12.5px` · `13.5px` 는 Figma 가
배율을 먹으며 생긴 값이고, `9px` · `19px` · `34px` 는 한 번씩만 쓰였다.
**사람이 고른 값이 아니다.**

### 글자 굵기 (`font-weight`)

400 · 600 · 700 셋뿐이라 여기는 깨끗하다. 다만 `admin` 은 400 을 두 번밖에
안 쓰고(medic 은 338회) 나머지가 전부 600 · 700 이다 — **어드민만 전체적으로
굵다.** 톤이 다르게 읽히는 실제 원인이다.

## 2. 정리한 것 — `frontend/css/tokens.css`

와이어프레임의 흩어짐이 구현으로 그대로 옮아왔는지 보았다. **토큰은 잘 짜여
있는데 화면이 그걸 안 쓰고 있었다.**

```
--radius: 10px 로 선언 · 실제 사용 2곳
그 밖의 15곳은 8px 을 직접 적음
```

색도 마찬가지였다. 하드코딩 여덟 자리가 남아 있었고, 그중 셋은 **거의 같은
연회색 세 가지**였다.

| 자리 | 전 | 후 | 왜 |
|---|---|---|---|
| 입력칸 안내글자 | `#9aa0a7` | `var(--ink-3)` | **흰 배경 대비 2.64 → 5.29.** AA 미달이었다 |
| 잠긴 버튼 채움 | `#9aa0a7` | `var(--disabled)` | 같은 값이 두 가지 뜻으로 쓰이고 있었다 |
| 숨김 토글 hover | `#f7f8f9` | `var(--bg)` | 셋이 눈으로 구별되지 않는 연회색이었다 |
| 알림 상자 바탕 | `#f4f6f7` | `var(--bg)` | 〃 |
| 끌어놓기 중 바탕 | `#f7f9fb` | `var(--bg)` | 〃 |
| 완료 배지 테두리 | `#cfe4d8` | `var(--done-line)` | 위험·주의에는 있는 토큰이 완료에만 없었다 |
| accent 위 글자 | `#ffffff` ×4 | `var(--on-accent)` | `--card` 와 값은 같지만 뜻이 다르다 |

모서리는 **쓰는 값에 이름을 붙이는 쪽**으로 맞췄다. 토큰이 화면을 안 따라가는
것보다, 토큰이 현실을 말하는 편이 낫다.

```css
--radius-sm:   6px    /* 배지 · 칩처럼 작은 것 */
--radius:      8px    /* 카드 · 입력칸 · 버튼 — 실제로 쓰던 값 */
--radius-pill: 999px  /* 상태 칩 */
```

`9px`(높이 17px 배지)과 `2px`(높이 4px 진행 막대)는 브라우저가 절반으로 자르는
**알약**이었다. 매직넘버를 지우고 `--radius-pill` 로 바꿨다 — 렌더 결과는 같다.

## 3. 손대지 않은 것과 그 이유

**글자 크기 토큰은 만들지 않았다.** 구현 쪽은 이미 11 · 12 · 13 · 15 · 17 · 22
로 일관돼 있어 고칠 불일치가 없다(`28px` 하나는 아이콘 글리프라 다른 것).
없는 문제를 고치면서 잘못 옮길 위험만 진다. `tokens.css` 머리말이 「위계는
크기가 아니라 굵기와 색으로 만든다」로 정해 둔 것과도 맞다.

**와이어프레임 HTML 은 고치지 않았다.** Figma 내보내기라 손으로 고쳐도 다음
내보내기에 지워진다. 위의 대조표가 디자인 쪽에 넘길 목록이다.

**`patient` 화면은 아직 구현이 없다.** 12px · 16px 로 몰려 있는 그쪽 둥글기는
그 화면을 만들 때 `--radius-lg` 를 더하면 된다 — 지금 미리 만들면 쓰이지 않는
토큰이 하나 는다.

## 4. 남은 것

- **`admin` 이 유독 굵다** — 400 을 거의 안 쓴다. 어드민 화면 구현 때 본문
  굵기를 정하고 와이어프레임에 되돌려야 한다.
- **잠긴 버튼의 글자 대비 2.64** — WCAG 1.4.3 은 비활성 요소를 예외로 두지만
  경계선이다. `KEY-106`(접근성)에서 다시 본다.
- **글꼴 순서가 다르다** — 와이어프레임은 `Pretendard` 를 먼저 두고, 구현은
  시스템 글꼴을 먼저 둔다. 맥에서 둘이 다르게 보인다. 어느 쪽을 정본으로
  할지 정해야 한다.
