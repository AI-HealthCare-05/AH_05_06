# KEY-277 생성 연결 및 검증 상태

Jira: https://leehee.atlassian.net/browse/KEY-277

## 이번 준비 범위

- KEY-276 검색 결과를 현재 DB와 다시 대조하는 `revalidate_guide_sources`.
- 승인·활성 버전·기관·URL·확인일·만료·병원·섹션·최소 점수·본문 해시 검증.
- 하나라도 불일치하면 전체 근거를 반환하지 않는다. 예외를 임의 본문으로 대체하지 않는다.
- 검증된 본문·문서/청크 ID·버전·기관·URL·확인일·점수·본문 해시를 frozen DTO로 복사한다.
- DTO의 본문은 repr에서 제외한다. 원문을 로그로 출력하지 않는다.

## 최초 준비 커밋의 범위 (후속 구현 전 기록)

최초 준비 커밋은 검색 결과 재검증까지만 구현했으며 운영 호출부가 없었다.
아래 「생성 연결 구현」이 그 이후 추가된 범위다. 준비 모듈 자체는 생성 허가가 아니다.

2026-09-10 [리뷰 결정](https://github.com/AI-HealthCare-05/AH_05_06/pull/286#issuecomment-5613664688)에서
KEY-82 평가 통과, KEY-276·KEY-83 병합 및 KEY-75 재사용을 확인했다.
외부 선행 블로커는 없으며, 아래 생성 연결은 KEY-277의 남은 구현 범위다.
기존 GuideService 상태기계를 확장하고 실제 연결 시 승인된 PocEvaluationApproval을 적용한다.

1. 확정 OCR·처방에서 식별정보 없는 검색 질의를 구성한다.
2. KEY-276 provider 결과를 프롬프트 직전에 재검증한다.
3. 안전 훅을 재사용하고, 근거가 없으면 승인·버전 고정 템플릿만 사용한다.
4. GuideSectionSourceSnapshot 1:N 모델·migration과 실제 영속 저장을 구현한다.
5. 섹션 재생성 시 이전 버전 근거 보존과 병원용 조회/표시를 연결한다.
6. 실패·반려·재생성·승인 E2E 및 이미지 빌드·Pilot 검증을 수행한다.

최초 준비 커밋의 frozen DTO는 메모리 복사다. 아래 후속 저장 기능을 생성 호출부에 연결해야 한다.
KEY-277 전체 인수조건 완료 또는 배포 준비로 표시하지 않는다.

## 재검증 반환 계약

`GuideSourceValidation`은 검증된 `sources`와 `block_reason`을 반환한다.
성공 시 사유는 None이며, 실패 시 근거는 항상 빈 tuple이다.
검색의 no_verified_context, source_conflict, index_invalid는 그대로 구분한다.
충돌·인덱스 오류 및 필드 불일치는 근거 없음 fallback으로 변환하면 안 된다.
근거 없음도 이 모듈이 템플릿 사용을 승인하는 것은 아니며 기존 admission gate를 거친다.
필드별 실패 사유에는 본문이나 환자 정보가 포함되지 않는다.
호출자는 검색과 재검증에 같은 min_similarity를 전달한다(기본 0.72).

## 생성 연결 구현 (2026-09-10)

- `GuideService.generate()`를 유지하며 `GUIDE_RAG_ENABLED=true`인 경우
  `GuideGenerationJob`에 접수하고 HTTP 202를 반환한다. AI 워커가 같은 서비스의
  생성·재생성·승인 상태 규칙을 사용한다. GuideStatus와 환자 챗봇 계약은 늘리지 않는다.
- KEY-82 §6의 승인자·승인일·평가 checksum을 가진 `KEY82_GENERATION_APPROVAL`을
  실제 `admit_generation_context` 호출에 전달한다. 평가셋·청킹·검색 임계값은 변경하지 않았다.
- 확정 OCR 게이트는 최신 develop의 KEY-288 다중 문서 기준을 재사용한다.
  질의에는 질환 enum과 카탈로그에 정확히 일치하는 확정 처방 이름만 쓴다.
  환자 이름·전화·차트번호·생년월일·OCR 자유 본문은 전달하지 않는다.
  카탈로그에 없는 처방명은 외부 전송하지 않고 `unrecognized_prescription`으로 중단한다.
- 검색 및 DB 재검증은 동일한 0.72 기준을 사용한다. 프롬프트 직전과 저장 직전에
  승인·병원·섹션·버전·본문 해시를 대조한다. 소스가 호출 도중 철회되면 저장하지 않는다.
- LLM 출력에 KEY-83 후검증과 처방 외 `drug_names` 검사를 적용한다.
  이는 규칙 기반 방어이며 자유 문장의 의학적 안전성을 완전히 증명하는 검사는 아니다.
  의사 승인 전 환자 접근은 계속 차단된다. 모델의 자기신고만으로 안전하다고 판단해서는 안 되며
  미등록 약물명·우회 표현에 대한 최종 의료 안전 리뷰가 필요하다.
- emergency는 기존 잠금 계약을 유지하여 승인된 고정 본문만 복사한다.
  고정 템플릿은 모델이 다시 쓰지 않으며, 승인자·날짜·현재 버전·본문 checksum이 모두
  기록된 DB 자료만 사용한다. 승인 기록이 없는 기존 범용 상수는 RAG fallback으로 사용하지 않는다.
- 생성 본문, 1:N 출처 스냅샷, 기존 생성 감사 이벤트, 안전검증 결과, 작업 완료를
  하나의 트랜잭션으로 저장한다. 저장 실패 시 부분 안내문을 남기지 않는다.
  생성 전 차단은 문서가 없으므로 같은 GuideSafetyCheck를 generation_job에 연결해 보존한다.
- 복약정보는 기존 `medication_body`가 확정 처방의 이름·빈도·기간만 조립한다.
  템플릿 본문 해시는 지도 문구 자체의 해시다. 저장 시 확정 처방을 다시 읽어 조립 결과까지 대조한다.
  원장님/의원 공통 문구는 기존 우선순위대로 `edited_body`에 적용하고,
  RAG/템플릿 `generated_body`와 출처를 덮어쓰지 않는다. 응급 고정 문구는 이 편집에서 제외한다.
- 요청 당시 OCR·처방·직원 편집 내용의 해시, 안내 버전, 실행 claim을 저장하고
  마지막에 재확인한다. 직원 권한 철회·입력 변경·만료된 claim은 저장할 수 없다.
- 의료진 `sections[].sources` 및 공용 원문 패널에 출처 기관·문서 ID·버전·확인일과
  fallback 여부·템플릿 ID/버전을 표시한다. 환자/챗봇에 원본 지식 접근을 추가하지 않는다.

### 실패 정책

| 조건 | 처리 |
| --- | --- |
| 근거 없음·승인되지 않은 지식만 존재 | 검증된 승인 템플릿만 사용, 없으면 차단 |
| 검색/재검증의 연결·시간 초과 | 최대 3회 큐 시도, 소진 시 승인 템플릿; 사유 `search_infrastructure_exhausted` |
| INDEX_INVALID | 생성 차단, 재인덱싱 필요; 템플릿으로 숨기지 않음 |
| SOURCE_CONFLICT·범위/메타데이터 불일치 | 생성 차단, 충돌·승인 상태 정정 필요 |
| LLM 호출 실패 | 최대 3회 시도 후 실패; 안내문·원문 미저장 |
| 잘못된 모델 응답·안전검증 차단 | 재시도 없이 실패, 고정 사유만 저장 |

재시도 대기는 2^attempts초이며 작업 lease는 300초다. 프로세스 장애 후 lease가
끝나면 다른 실행자가 새 claim으로 재개하며 이전 실행자는 저장할 수 없다.
검색 장애 fallback은 화면에 「검색 장애 → 템플릿」으로 표시하고,
워커에 `guide_generation_degraded` 오류 로그를 남긴다. 실제 운영 알림 수신은
Pilot의 로그 수집·알림 설정에서 별도로 확인해야 한다.

### migration 및 배포 전 확인

52번은 아직 머지되지 않은 이 PR의 migration이다. 기존 51번 모델 상태 전체 위에서
Aerich로 재생성하며, 스냅샷·작업 큐·안전검증의 작업 연결을 포함한다.
작업/근거 레코드가 존재하면 downgrade는 SQL 변경 전에 중단한다. 감사자료를 자동 삭제하지 않는다.

`GUIDE_RAG_ENABLED` 기본값은 false다. 최종 리뷰와 Pilot 검증 전에 생성 연결을
운영에서 임의 활성화하지 않는다. 활성화할 때는 API와 AI 워커에 같은 값을 주고
migration 52, 고정 revision 임베딩 모델, 승인된 지식/템플릿, OPENAI 설정을 먼저 확인한다.
KEY-323 생활관리 근거 보강은 후속 링크이며 이 PR의 평가 checksum을 바꾸지 않는다.

자동 검사에는 합성 DB와 합성 모델/임베딩 응답을 사용한다. 실제 환자 정보를
외부 모델에 보내지 않았다. 이미지 빌드와 로컬 자동검사가 Pilot 배포·수동 QA를
대체하지는 않는다. Pilot 8개 시나리오의 실측 결과와 금준님 최종 리뷰가 남으면
PR을 Draft로 유지한다.
