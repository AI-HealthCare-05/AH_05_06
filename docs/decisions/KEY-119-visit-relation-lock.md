# KEY-119 진료 관계 변경 잠금 결정 기록

상태: **리뷰 합의 대기 — 아직 v1 규범 계약이 아님**

## 목적

OCR 또는 승인 안내가 연결된 뒤 진료의 식별 관계가 바뀌어 의료문서·안내와 진료 정보가 어긋나는 것을 막는다. 큰 API 계약 변경은 구현 전에 공유하고 합의한다는 프로젝트 규칙에 따라, 아래 미결 항목을 코드보다 먼저 확정한다.

## 이미 병합된 동작

PR #69(KEY-135)에서 다음 동작이 `develop`에 병합됐다.

- `department_id`가 PATCH 본문에 있으면 잠금 여부를 먼저 확인한다.
- `OcrJob`이 하나라도 연결되어 있으면 `409 VISIT_LOCKED`다.
- 안내 상태가 `APPROVAL_PENDING` 또는 `SCHEDULED_TO_SEND`이면 `409 VISIT_LOCKED`다.
- `department_id: null`도 `department` 스냅샷 삭제이므로 잠금 대상이다.
- 타 병원 진료는 잠금 여부를 노출하지 않고 `404 VISIT_NOT_FOUND`다.
- `visit_summary`, `doctor_note`, `status`, `planned_stop`은 잠기지 않는다.

## KEY-119에서 합의할 항목

| 항목 | 현재 동작 | 제안 | 합의 |
|---|---|---|---|
| `department_id` | 잠금 | 그대로 유지 | 확정 필요 |
| `doctor_id` | 잠기지 않음 | 식별 관계로 보고 함께 잠금 | 확정 필요 |
| `visited_at` | 잠기지 않음 | 식별 관계로 보고 함께 잠금 | 확정 필요 |
| `visit_summary` | 잠기지 않음 | 비잠금 유지 | 확정 필요 |
| `doctor_note` | 잠기지 않음 | 비잠금 유지 | 확정 필요 |
| `status` | 잠기지 않음 | 비잠금 유지 | 확정 필요 |
| `planned_stop` | 잠기지 않음 | 비잠금 유지 | 확정 필요 |
| OCR 잠금 시점 | `OcrJob` 존재 즉시 | 기존 v1 유지 또는 `COMPLETED`/확정 필드 시점으로 축소 | 한금준 확인 필요 |
| 같은 값 재전송 | 필드가 본문에 있으면 차단 | 기존처럼 차단 또는 실제 변경일 때만 차단 | 확정 필요 |

## 구현 후 반드시 고정할 회귀 시나리오

- 미연결 진료에서 확정된 잠금 대상 필드 수정 허용
- OCR 연결 뒤 잠금 대상 필드 각각 `409 VISIT_LOCKED`
- 승인 안내 연결 뒤 같은 잠금 규칙 적용
- 비잠금 대상 필드는 연결 뒤에도 수정 가능
- `department_id: null` 스냅샷 삭제 정책 유지
- 타 병원 진료는 `404 VISIT_NOT_FOUND`
- 응답과 로그에 OCR 원문·승인 안내 본문·환자 실데이터·토큰 원문 미노출

## 구현 시작 조건

리뷰어 이희진과 OCR 연결 조건 협의자 한금준이 위 표의 잠금 필드·OCR 잠금 시점·같은 값 재전송 정책을 확정하면, 같은 KEY-119 브랜치와 Draft PR에서 계약 문서·서비스·테스트를 함께 갱신한다.
