# 판독 항목의 상태 어휘 v1 (KEY-109)

> 결정 2026-08-21 · 담당 권일준 · 리뷰어 이희진
> 근거: `#40`(KEY-62) 검수 · 와이어프레임 `S1-7`

`S1-7` 의 「이전 값 유지」·「이번 미시행」 버튼이 **눌러도 아무 일이 없어서 지웠다**.
둘 다 계약이 없었다. 이 문서가 그 둘과, 함께 얽힌 상태 넷을 정한다.

---

## 1. 어휘 — 넷을 가른다

지금은 「값이 없다」가 전부 한 덩이라 스탭이 무엇을 해야 하는지 알 수 없다.

| 상태 | 뜻 | 누가 말하나 | 스탭이 할 일 |
|---|---|---|---|
| `READ` | 읽었고 값이 있다 | 기계 | 맞는지 본다 |
| `UNREADABLE` | 문서에 있는데 **못 읽었다** | 기계 | **채워야 한다** |
| `PENDING_REPORT` | 문서가 「추후 보고 예정」이라 한다 | 기계 | **없다** — 기다린다 |
| `NOT_PERFORMED` | **이번엔 검사를 안 했다** | **사람** | 표시하고 넘어간다 |

`OcrJob.status = FAILED` 는 **작업 전체**의 상태다. 항목 상태와 층이 다르므로
같은 목록에 넣지 않는다 — 섞으면 「한 항목이 실패」와 「판독이 실패」가 구별되지
않는다.

### 누가 말했는지는 이미 남는다

`field_status` 를 새로 두되 **「누가」를 위한 칸은 만들지 않는다.** `OcrField` 가
이미 갖고 있다.

```
extracted_value · confidence      기계가 읽은 것
corrected_value · modified_by     사람이 고친 것
```

`PATCH` 로 상태가 바뀌면 `modified_by` 가 찬다. 비어 있으면 기계가 말한 것이다.
두 곳에 같은 값을 두면 어긋날 자리도 함께 생긴다.

## 2. 「확인할 항목」에서 무엇을 빼나

```
UNREADABLE       센다     문서에 값이 있는데 못 읽었다 — 사람이 넣어야 한다
PENDING_REPORT   뺀다     기다리는 것 말고 할 일이 없다
NOT_PERFORMED    뺀다     비어 있는 게 맞다
```

**`PENDING_REPORT` 를 세면 스탭이 영원히 막힌다.** AMH 결과가 두 주 뒤에 나오는데
그때까지 안내문을 못 만든다. 지금 `pending_report` 가 이미 빠져 있고(`ocr-review.js`
`counts`), `NOT_PERFORMED` 도 같은 자리에 넣는다.

`submit` 잠금은 지금대로 **`UNREADABLE` 과 값 충돌만** 막는다.

## 3. 「이전 값 유지」 — **하지 않는다**

기능을 미루는 것이 아니라 **하지 않기로 정한다.**

앞 진료의 검사값을 이번 판독에 복사하면, **옛 측정치가 이번 측정치의 자리에
앉는다.** 안내문은 그 자리를 「지금」이라고 말한다 —

```
빈혈 Hb   시작 10.2 · 지금 10.4 · 목표 12
                      ↑ 실제로는 석 달 전 값
```

의무기록이라 나중에 되짚을 근거가 없고, 값이 어디서 왔는지 화면에도 남지 않는다.

**대신 안내문이 출처와 날짜를 함께 말한다** — 「지난 검사 (05-20) 10.2」. 그건
`KEY-64`(안내문 생성) 몫이고, 지난 값을 담을 `lab_result` 표는 `KEY-136` 이
「계획」으로 남겨 두었다.

## 4. OCR 전체 실패 뒤 직접 입력 — v1 범위 밖

작업이 `FAILED` 면 결과가 없고, 결과가 없으면 **채워 넣을 항목 목록 자체가 없다.**
서버가 빈 골격을 만들어 주는 길을 v1 에 두지 않는다.

**재업로드가 1순위다.** 실패는 대개 사진이 흐리거나 잘린 것이고, 다시 찍는 편이
열 칸을 손으로 넣는 것보다 빠르고 정확하다. 손으로 넣은 오타는 그대로 의무기록이
된다.

`#40` 은 이미 그렇게 되어 있다 — 실패 화면에 [재업로드] 하나만 둔다. 「직접 입력」은
눌러도 안 되는 버튼이라 지웠다.

> 재업로드를 되풀이해도 실패하는 경우는 남는다. 그때는 **판독 없이 진료를
> 진행**하고 안내문을 손으로 쓰는 길이 필요한데, 그건 이 화면이 아니라 안내문
> 생성 쪽 결정이다.

## 5. 계약 변경

```
OcrField
  + field_status  READ | UNREADABLE | PENDING_REPORT | NOT_PERFORMED   기본 READ

PATCH /ocr/fields/{ocr_field_id}
  + field_status  선택. 사람이 보낼 수 있는 값은 NOT_PERFORMED 와 READ 뿐이다.
                  UNREADABLE · PENDING_REPORT 은 기계가 판정한다 — 사람이
                  보내면 400.
  기존 규칙 유지 — corrected_value 와 candidate_id 는 함께 못 보낸다.
                  field_status=NOT_PERFORMED 이면 값도 함께 보낼 수 없다.
                  「안 했다」면서 값을 적는 것은 앞뒤가 맞지 않는다.
```

되돌리기는 `field_status: "READ"` 로 보낸다. 잘못 눌렀을 때 빠져나갈 길이 없으면
스탭은 새 판독을 올린다.

## 6. 누가 무엇을 하나

* **이 문서 · 화면 표시** — `KEY-109` (여기)
* `PENDING_REPORT` 를 **서버가 내려주는 것** — `KEY-134` (한금준). 지금은 목업만
  `pending_report` 를 준다
* `field_status` **모델·마이그레이션·PATCH 구현** — 서버 몫. 표가 생기기 전까지
  화면은 목업으로 돈다
