# 패치 노트 — v2.3 → v2.3.1 (2026-08-18)

화면을 써 보며 나온 것을 담은 판. **64프레임**(62 → 64) · 라벨은 `A1`과 `P7`이 한 칸씩 밀림 · 상태 체계는 변경 없음.

## 배경 — 이번 판을 만든 것

1. **「신규냐 기존이냐」는 스탭이 답할 수 없는 질문이었다** — 등록 첫 화면이 그걸 먼저 물었다
2. **`A1-1`에서 재직 중인 직원을 손댈 길이 없었다** — 퇴사자 행에만 버튼이 있었다
3. 환자가 「가끔 놓쳐요」라고 답할 자리는 있는데 **거기에 해 줄 말이 없었다**
4. 환자 화면에 **지원하지 않는 것과 우리 몫이 아닌 것**이 글자로 남아 있었다 (카카오톡 채널명 · 119 · 네이버 예약)
5. **예시 처방이 실제와 달랐다** — 부인과 실제 처방은 야즈 단독이 대부분이다

## 변경 5건

### 1. `S1-2` + `S1-3` 통합 — 검색이 곧 분기다 ★

**전** — 첫 화면이 `[ 신규 환자 ][ 기존 환자 ]` 탭으로 갈라졌다.

이건 **스탭이 알 수 없는 것을 먼저 묻는 화면**이었다. EMR에 있는 환자라도 이 프로그램에는 없을 수 있고, 도입 초기에는 사실상 전부 신규다. 스탭은 둘 중 하나를 찍어야 하는데 찍을 근거가 없다.

**후** — 탭을 없애고 **환자 찾기 하나로 시작한다.** 이름이나 차트번호를 넣으면 아래에 결과가 뜨고, 그 결과 자체가 분기가 된다.

| 프레임 | 상태 | 무엇 |
|---|---|---|
| **`S1-2`** | 찾아서 고른다 | 검색 결과에서 한 명을 고른 상태 — 오른쪽에 **등록 전 확인**이 뜬다 |
| **`S1-3`** | 없으면 새로 만든다 | 결과에 없어 신규로 가는 상태 — **찾던 이름이 입력칸에 그대로 넘어온다** |

같은 화면의 두 상태다. `S1-6`~`S1-9`(판독 4상태) · `A1-2`/`A1-3`(직원 추가/수정)과 같은 짜임이다.

**부수 효과 하나 — 차트번호 중복이 걸리는 자리가 화면 끝에서 시작으로 옮겨졌다.** 전에는 신규 등록을 다 채우고 저장을 누른 뒤에야 「이미 있는 차트번호입니다」가 떴다. 이제 검색 단계에서 이미 그 환자가 보이므로, 중복 입력 자체가 잘 일어나지 않는다.

**레이아웃** — 내용영역 959px = 왼쪽 `flex:1`(487px) + gap 26 + 오른쪽 360px(등록 전 확인)

**표 컬럼** — 처음에 「지난 방문」 칸이 43px로 뭉개져 날짜가 안 보였다(필요 130px). 재배분했다.

```
mark 10 │ 이름 52 │ 생년월일 78 │ 휴대폰 96 │ 차트 52 │ 마지막 방문 flex(123)     gap 10
```

「지난 방문」 → **「마지막 방문」**으로 바꾸고 표에는 **날짜만** 넣는다.

**고른 근거** — 통합안 6개를 나란히 세운 시뮬레이션을 만들어 C(기존 환자를 골랐을 때)와 D(신규로 갈 때)를 골랐다. → [`sim-patient-register.html`](sim-patient-register.html) · 합성 환자 23명(동명이인 「김서연」 3명 포함)

### 2. `A1-1`에 `[ 수정 ]` · `A1-3` 직원 수정 신설 ★

**전** — 퇴사자 행에는 `[ 재직 처리 ]`가 있는데 **재직 중인 행에는 아무 버튼도 없었다.** 역할을 바꾸거나 퇴사시키는 길이 화면에 안 보였다.

| | |
|---|---|
| `A1-1` | 재직 중 6행 각각에 **`[ 수정 ]`** 추가 |
| **`A1-3`** | **직원 수정 — 신설.** `A1-2` 직원 추가와 같은 화면의 다른 상태 |

**`A1-3`이 `A1-2`와 다른 곳**

- 아이디는 **`🔒 잠김`** — 만든 뒤에는 바꾸지 않는다. 대신 `[ 비밀번호 재설정 ]`
- 역할은 이미 고른 것이 켜진 채로 (`☐관리자 ☐의사 ☑스탭`)
- 바닥이 좌우로 갈린다 — 왼쪽 **`[ 퇴사 처리 ]`** · 오른쪽 `[ 저장 ]`
- 「**서버가 막는 것 셋**」 상자 — 자기 자신의 관리자 해제 · 마지막 관리자 해제 · 자기 자신 퇴사

**번호가 밀렸다** — 어드민 **6 → 7**

### 3. `P7-3` 「가끔 놓쳐요」 펼침 신설 ★

챗봇 확인 질문에 「가끔 놓쳐요」 선택지는 있었는데 **고르면 나올 말이 없었다.**

**넣은 말** — 승인된 주의사항 문구를 그대로 재인용한다.

> **괜찮아요.** 가끔 놓치는 분이 많아요.
> 복용을 잊으셨다면 **생각난 즉시 드시고, 다음 약은 원래 시간에** 드세요.
>
> **잊지 않는 데 도움이 되는 것**
> · 매일 같은 시간에 알람을 맞춰 두세요
> · 칫솔처럼 **매일 보는 자리**에 약을 두세요
>
> ⓘ 이 답은 기록으로만 남습니다 — 따로 연락드리지 않아요

**🚨도 `[ 문의하기 ]`도 두지 않았다.** 응급이 아니고, 여기서 문의를 권하면 환자가 **「이건 문제구나」**로 읽는다. 그러면 다음엔 말하지 않는다. `P7-2`(먹고 있는데 불편해요)와 같은 원리다.

**「⚠ 챙겨주세요」에 넣지 않는다** — 기록으로만 남는다.

### 4. 화면에서 지운 글자 — 우리 몫이 아닌 것

| 무엇 | 어디 | 왜 |
|---|---|---|
| `〇〇여성의원 카카오톡 채널` | 환자 6곳 · 의료진 `S1-12`·`D1-2` **4곳** | 버튼이 어디로 가는지는 눌러 보면 안다. 의원 이름을 화면마다 박아 두면 의원이 바뀔 때 전부 손봐야 한다 |
| `밤이나 휴일이면 119` | 환자 1곳 | **119는 우리가 안내할 자리가 아니다.** 응급 판단을 화면이 대신하는 꼴이 된다 |
| `네이버 예약 · 카카오톡 채널` | 환자 `P5-1`·`P5-2` | 예약·문의 주소는 의원 설정(`A1-4`)에서 정한다. 어느 서비스인지는 화면에 쓸 일이 아니다 |

의료진 `S1-12`·`D1-2`의 **왼쪽 원문**에서는 `💬 문의하기 · 〇〇여성의원 카카오톡 채널` 중 채널 이름만 뗐다 — 환자 화면에 버튼은 그대로 있으므로 원문에도 `💬 문의하기`는 남는다.

**남긴 것 둘** — 환자에게 안 보이는 설계 메모다.
- `S1-12`/`D1-2`의 「문의 주소」 상자 — 「병원 설정(`A1-4` 의원 정보)의 카카오톡 채널 주소를 그대로 쓴다 — 이 화면에서 고치지 않는다」
- `A1-4` 입력칸 도움말 — 「ⓘ 환자 화면 「문의하기」가 열리는 카카오톡 채널 주소입니다」

### 5. 환자 화면 예시 처방을 야즈 단독으로

**전** — 다낭성난소증후군 예시가 `야즈 + 메트포르민` 병용이었다. 부인과 실제 처방은 **야즈 단독이 대부분**이다.

| 프레임 | 바꾼 것 |
|---|---|
| 행 3 제목 | `다낭성난소증후군 · 야즈 + 메트포르민 ★` → **`· 야즈 ★`** |
| `P2-2` 처방받은 약 | 구분선 + 메트포르민 3줄(성분 · 용법) 삭제 |
| `P2-2` 약별 복용 방법 | 「메트포르민은 식사 직후에…」 삭제 |
| `P3-2` 제목 | `야즈정 · 메트포르민 드시는 동안` → **`야즈정 드시는 동안`** |
| `P3-2` 이런 건 알려주세요 | 「메트포르민은 처음 몇 주 속이 불편하거나…」 문단 삭제 |
| `P5-2` 머리줄 | `처방 · 〇〇여성의원 · 약 2개` → **`· 〇〇여성의원`** |
| `P5-2` 야즈 카드 | **`먼저 떨어져요` 배지 삭제** — 약이 하나면 「먼저」가 성립하지 않는다. 테두리도 `P5-1`처럼 1px |
| `P5-2` 메트포르민 카드 | 통째 삭제 |
| `P5-2` 소진 안내 | `야즈가 먼저 소진돼요` → **`약이 소진돼요`**. 이유 문장의 「혈당이 오르는 것을 돕는」(메트포르민 몫)을 빼고 `P2-2`와 같은 말로 통일 |

**예시에서만 뺀다 — 제품에서 빼는 게 아니다.** `content/prescription-sets.md`의 세트 정의, `review-draft-cautions.md`의 `CAU-MET-01`(위장 불편), 의료진 `S2-3` 세트 목록과 `D2` 대시보드는 그대로다. 병용 처방이 들어오면 화면은 여전히 카드를 두 개 그린다.

**남긴 것** — `P4-2` 생활관리의 「혈당이 천천히 오르는 식사」. 메트포르민이 아니라 PCOS 자체(인슐린 저항성) 관리라 약과 무관하게 유효하다.

**생긴 구멍 하나** — 「약이 두 개면 카드가 두 개다」 규칙은 살아 있는데 **그걸 보여주는 프레임이 없다**(`P5-1`·`P5-2` 둘 다 카드 하나). 개발자가 규칙만 보고 만들어야 한다. `wireframe-spec-patient.md`에 경고로 적어 뒀고, 메우려면 `P5-3`(병용 · 카드 2개)를 하나 세우면 된다.
