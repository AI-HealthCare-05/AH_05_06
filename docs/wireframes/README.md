# 와이어프레임

화면 정의의 **정본**이다. 구현 중 화면 질문이 생기면 여기를 먼저 본다.

의료진은 **3.0.0**(아래), 환자 모바일은 **`P2~P5` 3.0.0 · 나머지 2.3.1**,
어드민은 **`A1-1` 만 3.0.0 에 실렸고 `A1-2~7` 은 2.3.1** 이다.

## 지금 판 — 3.0.0 (의료진) · 화면 22

**[`wireframe-medic-3.0.0.html`](wireframe-medic-3.0.0.html)** — 파일 하나를 열기만 하면 된다.
서버도 빌드도 필요 없다.

```
L-1  L-3
S1-1 S1-2 S1-4 S1-6
S1-11 복약지도  S1-12 주의사항  S1-13 생활지도  S1-14 문자 설정   스탭 확인
D1-1 복약지도   D1-2 주의사항   D1-3 생활지도   D1-4 문자 설정   최종 확인 (의사)
D1-6 현황
S2-1 S2-3 S2-4
D2-3 D2-4 D2-5
A1-1
```

앞 판까지는 손으로 그린 그림이었다. 이 판은 **돌아가는 화면을 띄워 그대로 담는다** —
그림과 코드가 어긋날 자리가 없다. 사람이 쓰는 것은 화면마다 붙은 **「왜 이렇게
생겼는가」** 뿐이고, 그림은 앱이 그린다.

화면마다 제 문서를 갖고 그 안에 **그 화면이 실제로 싣는 CSS만** 들어간다. 한 벌로
몰아 담았더니 로그인에 `blocks.css` 가 섞여 이름표가 옆으로 붙고 단추가 빨개졌다 —
화면마다 싣는 것이 다르다.

### 다시 만들기

화면을 고쳤으면 로컬 서버를 띄우고 <http://localhost/_make-wireframe.html> 를 한 번 연다.
1~2분 뒤 새 파일이 내려받아지고, 그것으로 이 자리를 덮는다.

**손으로 고치지 않는다.** 담을 화면과 상태, 그리고 「왜 이렇게 생겼는가」만
`frontend/_make-wireframe.html` 의 `FRAMES` 에서 고친다.

## 고치는 법

3.0.0 은 위 「다시 만들기」를 쓴다. **앞 판(2.3.1)은 고치지 않는다** — 지나간 판이다.

## 화면 ID는 팀 공용 이름이다

`S1-6` · `P7-3` 같은 ID로 티켓 · PR · 버그 리포트에서 화면을 부른다.
합성 데이터 시나리오도 이 ID로 화면과 이어진다 — [`../synthetic-data-spec.md`](../synthetic-data-spec.md).

**ID를 바꾸지 않는다.** 화면이 없어지면 ID도 없애되, 남은 ID를 당겨 쓰지 않는다.

## 여기 없는 것

| 무엇 | 어디 |
|---|---|
| 화면별 상세 명세 (필드 · 상태 · 예외) | 기획 저장소 `spec-medical.md` · `spec-admin.md` · `spec-patient.md` |
| 안내 문구 원문 · 처방 세트 | 기획 저장소 `content/` |
| 환자 화면 **디자인**(색 · 글자 · 여백) | 별도 진행 중 — 와이어프레임은 **뼈대**이고 디자인은 아직 여기 없다 |

## 규칙

- 화면 안의 이름 · 차트번호 · 연락처는 **전부 지어낸 것**이다. 실제 환자 자료를 넣지 않는다
- 담당의는 **박연 원장 · 김연우 원장** 둘로 통일한다 (합성 데이터 CSV와 같다)
- 의원 이름은 **「여성의원」** — 가상 브랜드를 새로 만들지 않는다
