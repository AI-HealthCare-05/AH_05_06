## 보는 법

파일을 브라우저로 열기만 하면 된다. **빌드도 서버도 필요 없다** — HTML 한 장에 CSS가 들어 있다.

```bash
open docs/wireframe/wireframe-medic-2.3.1.html
```

프레임마다 **설계 주석**이 함께 있다. 「왜 이렇게 생겼는가」가 화면 옆에 적혀 있으니, 구현 전에 그 문단을 읽어 주세요. 화면만 보고 만들면 의도가 빠집니다.

## 고치는 법

> **원본을 직접 고치지 않는다.** 552KB짜리 한 장이라 중간에 태그가 어긋나면 어디서 깨졌는지 찾기 어렵다.

1. `work-wireframe-medic-2.3.1.html`처럼 **사본을 만들어** 거기서 고친다
2. 태그 균형을 확인한다 — 여는 태그와 닫는 태그 수가 맞는지
3. 브라우저에서 **해당 프레임과 그 앞뒤를 눈으로 확인**한다
4. 통과하면 원본을 갱신하고 사본을 지운다

프레임을 **더하거나 뺐다면** 이 README의 프레임 수와 `PATCH` 노트도 같이 고친다.

## 화면 ID는 팀 공용 이름이다

`S1-6` · `P7-3` 같은 ID로 티켓 · PR · 버그 리포트에서 화면을 부른다.
합성 데이터 시나리오도 이 ID로 화면과 이어진다 — [`../synthetic-data-spec.md`](../synthetic-data-spec.md).

**ID를 바꾸지 않는다.** 화면이 없어지면 ID도 없애되, 남은 ID를 당겨 쓰지 않는다.

## 여기 없는 것

| 무엇 | 어디 |
|---|---|
| 화면별 상세 명세 (필드 · 상태 · 예외) | 기획 저장소 `spec-medical.md` · `spec-admin.md` · `spec-patient.md` |
| 안내 문구 원문 · 처방 세트 | 기획 저장소 `content/` |
| 환자 화면 **디자인**(색 · 글자 · 여백) | 별도 진행 중 — 와이어프레임은 **뼈대**이고 디자인은 아직 여기 없다 |

## 규칙

- 화면 안의 이름 · 차트번호 · 연락처는 **전부 지어낸 것**이다. 실제 환자 자료를 넣지 않는다
- 담당의는 **박연 원장 · 김연우 원장** 둘로 통일한다 (합성 데이터 CSV와 같다)
- 의원 이름은 **「여성의원」** — 가상 브랜드를 새로 만들지 않는다
