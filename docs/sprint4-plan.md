## 1. 이번 주 성격

`project_workflow.md`의 Sprint 4 원안은 "Walking Skeleton → MVP 기능 확장"이다. 그러나 8/31 멘토링 피드백은 기능 추가보다 **구조 정리와 시연 안정화**를 우선하라는 것이다.

- "기능 추가보다는 개발환경에서 동일한 migration·스키마·seed가 유지되고, 안전하게 성공/안전하게 실패하는 서비스로."
- "깃헙에서 다운받아 구동하는데 5분 내로. 프론트와 구현 영역이 잘 연결되도록."
- "pilot 전체 구조 정리 및 최대한 시연 가능하게. OCR 안정성 확보."
- "OTP가 안 돼서 GET을 그냥 열었다고 하면 안 된다." 개발·데모는 고정값 `000000`.
- "SMS는 개발용·시연용을 따로 두는 방법도 고려."

**따라서 이번 주 목표를 "시연 가능한 골격 굳히기(hardening)"로 재정의한다.** 새 기능은 MVP 데모 흐름을 끊는 블로커 3개만 닫는다. 발송 이력·직원 관리·어드민·병원별 설정·PDF·UI 고도화는 이번 주 범위 밖이다.

데모 흐름(끊김 없이 완주해야 하는 대상):

```text
스탭 검토 → 의사 승인 → 환자 링크 발급·표시 → 고정 OTP(000000) 인증 → 가이드 열람 → D+7 체크인
```

## 2. 우선순위

### P0-A. 5분 안에 clone → run

목표: `git clone` 후 신규 개발자가 5분 안에 로그인 화면까지 도달한다.

- 단일 진입점(`make dev` 또는 `docker compose up` + seed) 하나로 정리하고 README에 그 명령만 남긴다.
- migration을 최소 세트로 정리한다. Pilot마다 스키마가 갈라진 부분을 동일 migration·동일 스키마로 통일한다.
- seed 재현성: 같은 seed 명령이 항상 같은 계정·합성 환자·진료를 만든다([`qa/KEY-36-test-accounts-and-fixtures.md`](qa/KEY-36-test-accounts-and-fixtures.md) 기준).
- "안전하게 실패": migration·seed 실패 시 명확한 에러로 중단하고 부분 상태로 남기지 않는다.
- `README.md` 한글 깨짐 수정 + Quickstart 절 정리.
- 검증: 초기화된 환경에서 절차대로 실행해 소요 시간과 실패 지점을 [`local-health-check.md`](local-health-check.md)에 기록한다.

### P0-B. 환자 인증 흐름 정리 (즉시 블로커 1)

- OTP 미구현을 이유로 환자용 GET을 무인증으로 열어 둔 임시 우회를 **제거**한다. 해당 위치를 먼저 코드에서 찾아 목록화한다.
- OTP 단계는 유지한다. 개발·로컬·테스트에서만 `MOCK_OTP_CODE=000000` 입력 시 통과한다.
- 운영에서는 `MOCK_OTP_CODE`가 설정돼도 우회가 동작하지 않는다. KEY-200 시딩 게이트(환경변수 + 조건 이중 확인)와 같은 패턴을 재사용한다.
- 링크 유효성·만료·폐기 검사와 5회 실패 잠금(`OTP_LOCKED` / `Retry-After`)은 우회하지 않는다.
- FE의 6자리 입력·재발송 타이머를 실제 검증 API에 연결한다(`P1-2`).
- 근거: [`구현현황.md`](구현현황.md) §3, §4.1, §7.

### P0-C. SMS mock 분리

- 발송 수단을 어댑터 인터페이스 하나로 추상화한다. 개발용 mock / 시연용 mock 구현을 두고 실제 공급자는 이후 교체만 하도록 남긴다.
- 지금은 "발송 성공" 상태 + 서버 로그 확인만 제공한다. 토큰·인증번호 원문은 로그에 남기지 않는다([`qa/KEY-48-log-masking-review.md`](qa/KEY-48-log-masking-review.md)).

### P0-D. OCR 확정값 전송 (진단 B1)

- `frontend/js/` 전체에서 `confirm:true`를 전송하는 코드가 0건이라, 서버 확정 처리(`app/ocr/service.py`, `is_confirmed`)가 완비돼 있어도 실서버에서 안내 생성이 전량 `422 OCR_NOT_CONFIRMED`로 막힌다.
- 확정 버튼에 `{confirm: true}` 전송을 연결한다. 서버 변경 없음, 규모 0.5인일.
- 미조치 시 P1-A(링크 발급·표시)·P1-B(OCR 안정성) 검증이 불가능하다. **P0 게이트로 취급한다.**
- 근거: 권일준 진단 §4.2 / [`work-packages.md`](work-packages.md) WP-D.

### P1-A. MVP 데모 흐름 나머지 블로커 (블로커 2·3)

- 블로커 2: 의사 승인 직후 환자 링크 **발급·화면 표시·복사**를 연결한다([`qa/KEY-205-patient-link-launch.md`](qa/KEY-205-patient-link-launch.md) 확인).
- 블로커 3: 스탭 검토 → 의사 승인 요청 **상태 전환**을 확인한다. 별도 Submit API가 필요한지, 기존 상태 전환 API로 충분한지 먼저 조사한 뒤 연결한다(`S1-11~S1-13`).

### P1-B. OCR 안정성

- 실패·타임아웃·재시도 경로를 정리한다. `S1-10`의 재시도 API와 명확한 실패 상태를 추가한다.
- 합성 문서 fixture([`ocr-fixtures.md`](ocr-fixtures.md))로 반복 실행 시 동일 결과가 나오는지 확인한다.

### P2. 구조 정리 (WP-S)

- 권일준 전체 구조 진단(210건)은 완료됨. 프론트·백 충돌 지점, 미완성 구현 63건 목록은 [`work-packages.md`](work-packages.md) WP-S로 이관.
- 이번 주(1주차) 실행: `openapi.json` 저장소 편입 + CI 감지, 목업을 서버 DTO에 종속, 공용 모듈 강제 + 버튼-핸들러 연결 검사 테스트, 미완성 63건을 삭제 / 3단계 안내화면(WP-F)으로 분류.
- 전면 재구성은 Sprint 5.

## 4. 완료 기준

- 초기화된 환경에서 문서 절차대로 5분 내 로그인 도달을 1회 이상 확인하고 소요 시간을 기록했다.
- §1의 데모 흐름을 고정 OTP `000000`으로 처음부터 끝까지 `?mock=1` 없이 1회 완주했다. 확정 → 안내 생성 단계(B1)가 실서버 응답으로 통과한다.
- 무인증 우회 경로가 제거되고, 운영 설정에서 `MOCK_OTP_CODE`가 우회를 열지 않음을 테스트로 확인했다.
- OCR 실패·재시도가 합성 fixture로 재현·통과된다.
- 링크 토큰·OTP 원문이 화면·로그에 노출되지 않는다.
- `README.md` 한글 깨짐이 수정되고 Quickstart가 최신 명령과 일치한다.
- 관련 테스트와 기존 핵심 흐름 회귀가 통과한다. 실행하지 못한 검증은 PR에 사유를 기록한다.
