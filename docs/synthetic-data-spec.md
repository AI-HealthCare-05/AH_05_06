# 합성 데이터 명세 — 환자 · 진료 · 처방 · 검사결과

> `KEY-13` · 하위 `KEY-27`(시나리오 매트릭스) · `KEY-30`(필드 매핑)
> 기준 — 와이어프레임 v2.3.1 (64프레임) · 2026-08-19

개발 · 데모 · QA에서 **실제 환자정보를 한 건도 쓰지 않기 위한** 규격이다.
FE · BE · OCR · LLM · QA가 **같은 시나리오 ID로 같은 데이터를 부른다.**

---

## 1. 절대 규칙

| | |
|---|---|
| **실제 환자 데이터 금지** | 원본은 물론이고 **실환자를 변형한 값도 쓰지 않는다.** 이름 · 생년월일 · 전화번호 · 차트번호 전부 지어낸 것이다 |
| **실제 연락처 금지** | 휴대폰은 `010-XXXX-XXXX` 꼴이되 **실제 가입자와 겹칠 수 있다** — 문자 발송 대상에 절대 넣지 않는다. 개발·테스트 환경은 발송을 콘솔 출력으로 대체한다.<br>**발송 차단 자체는 이 문서가 아니라 코드가 막는다** — `KEY-33`(안전 검수) · `KEY-29`·`KEY-36`(시드·fixture) |
| **출처 표기** | 검사 수치와 안내 문구는 식약처 의약품정보와 원장님 검수본에서 왔다. 임의로 만들지 않는다 |
| **한 곳에서만 고친다** | 정본은 `docs/data/` 아래 CSV 둘뿐이다 — 환자와 직원. 코드에 값을 박지 않는다 |

## 2. 시나리오 ID

```
SYN-{질환}-{번호}

  SYN-EMS-01 ~ 10    자궁내막증        비잔                    ← 손으로 고른 케이스
  SYN-PCOS-01 ~ 09   다낭성난소증후군   야즈 · 메트포르민         ← 손으로 고른 케이스
  SYN-BOTH-01        두 질환 동시
  SYN-DUP-01 ~ 11    동명이인 네 무리    검색·선택 화면용
  SYN-BULK-001 ~ 069 일반               목록·필터·날짜 분포용
  SYN-CHK-01 ~ 05    확인 문자 응답 5종  (환자가 아니라 응답이다)
```

**앞의 31행과 뒤의 69행은 쓰임이 다르다.**
`EMS` · `PCOS` · `BOTH` · `DUP`는 **한 행마다 이유가 있다** — 아래 매트릭스가 그 이유다. 함부로 값을 바꾸면 그 화면을 못 본다.
`BULK`는 **목록이 한 화면에 안 들어갈 때, 필터가 걸릴 때, 날짜가 흩어질 때**를 보려고 넣었다. 개별 행에 의미는 없다.

```
100명 · 진료 99건 · 69일에 분산 (2026-01-07 ~ 2026-08-15)
자궁내막증 49 · 다낭성 46 · 두 질환 4        검사한 방문 52 / 안 한 방문 47
통수로 적힌 처방 33                          수신 거부 4
```

**이 ID가 팀 공용 이름이다.** 티켓 · 테스트 · 픽스처 · 버그 리포트에서 이 ID로 부른다.
차트번호(`12401`)는 화면에 보이는 값이고, 시나리오 ID는 **팀이 서로에게 쓰는 값**이다.

### 동명이인 — 등록 화면(`S1-2`)의 핵심 위험

`S1-2`는 검색 결과에서 **엉뚱한 사람을 고르면 안 되는** 화면이다. 잘못 고르면 남의 처방이 남의 폰으로 간다.
그래서 **난이도를 나눈 네 무리**를 둔다.

| 무리 | ID | 이름 | 생년월일 | 차트 | 폰 뒤 4자리 | 무엇을 보는가 |
|---|---|---|---|---|---|---|
| **①** | `SYN-DUP-01` | 김서연 | 1975-03-09 | 10737 | 2271 | **기본** — 생년월일이 다르다. 이름만으로는 못 고른다 |
| | `SYN-DUP-02` | 김서연 | 1988-07-14 | 08157 | 5439 | |
| | **`SYN-DUP-03`** | **김서연** | **1990-01-01** | **12345** | 4085 | ← **표준 데모 환자** |
| **②** | `SYN-DUP-04` | 이서윤 | **1994-05-21** | 09817 | **4153** | **최악** — 이름도 생년월일도 같다. |
| | `SYN-DUP-05` | 이서윤 | **1994-05-21** | 10878 | **4156** | **폰 뒷자리로만 갈리는데 그마저 3 차이다** |
| **③** | `SYN-DUP-06` | 박지우 | 1993-02-08 | 09562 | 1491 | **같은 해 다른 날** — 연도만 보고 넘기면 틀린다 |

**무리 ②가 이 화면의 진짜 시험이다.** 이름과 생년월일이 둘 다 같으면 화면이 더 보여줄 것이 없다.
차트번호와 폰 뒷자리를 **결과 줄에 함께 띄우지 않으면 고를 방법이 없고**, `4153`과 `4156`은 급하면 헷갈린다.
여기서 잘못 고르는 것을 막지 못하면 나머지 셋을 막아도 소용없다.

`SYN-DUP-03`은 **환자 화면 디자인 목업이 쓰는 그 사람**이다 — 디자인 · 시드 · 데모가 같은 한 명을 본다.

> **일반 행에서도 이름이 겹친다.** `강예린` · `서유나`가 각각 둘, `박지우`는 일반 행이 하나 더 붙어 셋이다.
> 일부러 만든 것이 아니라 100명을 뽑으니 그렇게 됐다 — **실제 의원에서 겹치는 방식과 같다.**
> 동명이인은 특별한 사건이 아니라 **평상시에 늘 있는 일**이라는 뜻이므로, 그대로 둔다.

## 7. 모자란 것 — 다음에 채운다

| 무엇 | 왜 필요한가 | 어떻게 |
|---|---|---|
| **`S1-8` 두 곳에 있음** | 같은 검사가 EMR과 검사지 양쪽에 **다른 값**으로 있을 때. 검사일이 최근인 쪽을 쓴다 | 기존 환자 하나에 **검사지 한 장을 덧붙여** 만든다 — 새 환자를 늘리지 않는다 |
| **`S1-10` 생성 실패** | 판독은 됐는데 조립이 실패한 상태. 나가는 길 셋이 다 살아 있는지 봐야 한다 | 데이터가 아니라 **주입 실패**로 만든다 — 시드가 아니라 테스트 더블의 몫 |
| **저신뢰 값** | 티켓의 「저신뢰」 케이스. OCR 신뢰도가 낮아 사람이 확인해야 하는 값 | OCR 결과에 신뢰도 칸이 생긴 뒤 (`KEY-2` 영역) |

**`S1-10`과 저신뢰는 환자 데이터로 만들 수 없다** — 처리 과정의 실패라 픽스처가 아니라 **테스트 더블**이 맡는다. `KEY-14` 시드 스크립트 범위 밖이다.

### 이 표는 사람이 지키는 것이 아니라 검사가 지킨다

위 표의 정본은 문서가 아니라 **`app/tests/fixtures/mapping.py`**다.
이 절은 그것을 사람이 읽으라고 옮겨 적은 것이고, 둘이 갈리면 **검사가 먼저 깨진다.**

`app/tests/fixtures/test_field_mapping.py`가 매번 확인한다.

| 무엇 | 왜 |
|---|---|
| CSV 33칸이 **하나도 빠짐없이** 표에 있는가 | 빠지면 시드가 그 값을 어디 넣을지 **스스로 정한다** |
| 표에만 있고 CSV에 없는 유령 칸이 없는가 | 칸 이름을 바꾸면 여기서 걸린다 |
| 저장한다면 **필드명이 있는가** · 저장 안 하면 **이유가 적혀 있는가** | 이유가 없으면 다음 사람이 억지로 컬럼을 만든다 |
| 적어 둔 타입대로 값이 **실제로 읽히는가** | `date`라 써 놓고 `2026/08/19`면 또 해석해야 한다 |
| enum 값이 **정의 밖으로 나가지 않는가** | |
| 정의한 enum 값이 **절반 넘게 안 쓰이지 않는가** | 안 쓰이는 상태는 화면에서 볼 수 없다 |

### 「필드명이 API 계약과 일치」 — 계약은 코드가 만든다

**API 명세서를 손으로 관리하지 않는다.** FastAPI가 코드에서 OpenAPI를 뽑는다.

```
GET /api/openapi.json     ← 손으로 적는 곳이 아니다. 코드가 바뀌면 따라 바뀐다
GET /api/docs             ← 사람이 보는 화면
```

`TestFieldNamesAgainstOpenApi`가 그 스키마와 위 표를 대조한다.
지금은 **환자·진료 API가 없어 skip**되고, `KEY-12`·`KEY-16`으로 생기는 순간 **저절로 켜진다.**

> **여기서 보는 것은 이름뿐이다.** 타입(`string` · `integer` · `date-time` …)까지 맞추는
> 자동 검증은 **`KEY-32`** 몫이다. 이름이 어긋나면 타입을 볼 필요도 없이 시드가 깨지므로,
> 이 검사는 **먼저 걸러 내는 자리**다.

이렇게 두면 유지할 문서가 늘지 않는다 — 코드가 바뀌면 검사가 알려 주고,
누군가 노션이나 별도 저장소에 같은 내용을 옮겨 적을 필요가 없다.

> **못 다룬 것 —** OpenAPI는 「`401`이 난다」는 알려주지만 **「`401`을 두 종류로 나눠야 한다」**는 못 알려준다.
> 그런 규칙은 와이어프레임의 설계 주석과 [`auth-contract.md`](auth-contract.md)가 갖는다.
> **필드·타입은 코드가, 「왜 그렇게 생겼는가」는 화면이** 정본이다.

## 9. 직원 계정 — `docs/data/synthetic-staff.csv`

환자와 별개다. **환자는 계정이 없고, 직원은 진료 대상이 아니다.**
`L-1`~`L-3` 로그인과 `KEY-23` 권한 매트릭스가 쓴다.

### 비밀번호는 이 파일에 없다

`AGENTS.md` — 「비밀번호를 코드 · 화면 · 로그 · 커밋에 남기지 않는다」.

시드가 **환경변수 `SEED_STAFF_PASSWORD`에서 받아** 17개 계정에 같은 값을 넣는다.
**기본값을 두지 않는다** — 값이 없으면 시드가 실패한다.

이러면 합성 계정이 실수로 운영 DB에 들어가도 **아무도 로그인할 수 없다.**
저장소에 비밀번호가 없으니 새어 나갈 것도 없다.

### 17개 계정

| ID | 병원 | login_id | roles | 무엇을 보는가 |
|---|---|---|---|---|
| `SYN-STAFF-01` | H1 | `staff01` | staff | **기준 스탭** — 다른 시험의 기본값 |
| `SYN-STAFF-02` | H1 | `doctor01` | doctor | **기준 의사** — 환자 CSV 담당의 대부분(박연) |
| `SYN-STAFF-03` | H1 | `doctor02` | doctor | 두 번째 의사 — `D2-3` 본인 소유 검사에 둘이 필요하다 |
| `SYN-STAFF-04` | H1 | `admin01` | admin | **운영만** — 진료 화면이 열리지 않아야 한다 |
| `SYN-STAFF-05` | H1 | `both01` | staff·doctor | 겸직 |
| **`SYN-STAFF-06`** | H1 | `adminstaff01` | **staff·admin** | ★ **의료 승인 차단의 그 계정** |
| `SYN-STAFF-07` | H1 | `admindoc01` | doctor·admin | admin이 승인을 방해하지 않는다 |
| `SYN-STAFF-08` | H1 | `allthree01` | staff·doctor·admin | 합집합이 제대로 도는가 |
| **`SYN-STAFF-09`** | H1 | `newbie01` | staff | ★ **첫 로그인** — `L-3` 없이는 아무 데도 못 간다 |
| `SYN-STAFF-10` | H1 | `newdoc01` | doctor | 첫 로그인 의사 — 역할이 있어도 `L-3`이 먼저다 |
| **`SYN-STAFF-11`** | H1 | `left01` | staff | ★ **퇴사자** — `roles`가 남아 있어도 거부된다 |
| `SYN-STAFF-12` | H1 | `leftdoc01` | doctor | 퇴사한 의사 — 지난 진료의 담당의로는 이름이 남는다 |
| **`SYN-STAFF-13`** | H1 | `lock01` | staff | ★ **5회 실패 잠금 전용** |
| `SYN-STAFF-14` | H1 | `lastadmin01` | admin | 마지막 관리자 — 그 **의원의** admin을 빼는 저장은 거부돼야 한다 |
| `SYN-STAFF-15` | **H2** | `staff21` | staff | 다른 의원 스탭 — `H1` 환자·진료가 보이면 안 된다 |
| **`SYN-STAFF-16`** | **H2** | `doctor21` | doctor | ★ **다른 의원의 동명이인 의사(박연)** — 이름으로만 풀면 `H1` 박연과 섞인다 |
| `SYN-STAFF-17` | **H2** | `admin21` | admin | 다른 의원 관리자 — `H1` 직원 목록에 닿으면 안 된다 |

`roles`는 CSV 한 칸에 `|`로 이어 적는다(`staff|admin`). 쉼표는 CSV 구분자와 겹친다.
**역할 조합 7가지가 모두 들어 있다** — `KEY-23` 매트릭스의 `VALID_COMBINATIONS`와 같다.

### 의원이 둘이다 — `H1` · `H2`

`H1`이 기준 의원이고 환자 CSV도 전부 여기다. `H2`는 **격리 확인용**이다.

병원 격리는 이 서비스에서 제일 중요한 경계인데(`docs/contracts/patient-visit-api-v1.md` 5절
— 타 병원 리소스는 `403`이 아니라 **존재를 감추는 `404`**), 의원이 하나뿐이면
「안 보인다」가 격리 때문인지 자료가 없어서인지 구분되지 않는다. 그래서 `H2`에
**스탭·의사·관리자 셋 다** 둔다.

`SYN-STAFF-16`은 **`H1`의 박연(`doctor01`)과 이름이 같다.** `app/tests/fixtures/mapping.py`가
담당의를 「이름 → 직원 픽스처로 푼다」고 적어 두었는데, 이름만 보고 풀면 남의 의원 의사를
집는다. 그 상황을 실제로 만들 수 있어야 그 코드를 검사할 수 있다.

「마지막 관리자」도 **의원 단위 규칙**이다 — 옆 의원에 관리자가 있다고 이 의원이
관리자 없이 남아도 되는 것이 아니다. `admins_besides()`가 같은 의원만 센다.

실제 `hospital_id`는 bigint라(`patient-visit-api-v1.md` 2절) DB가 넣을 때 발급한다.
CSV의 `H1`·`H2`는 **어느 의원 소속인지만** 나타내는 표식이다.

### `lock01`을 다른 시험이 쓰면 안 된다

로그인 실패 카운터는 **계정이 아니라 입력된 아이디 문자열**에 붙는다
(`docs/auth-contract.md` 3절 — 없는 아이디도 똑같이 세야 존재 여부가 안 새어 나간다).

그래서 잠금 시험이 다른 시험과 계정을 나눠 쓰면 **순서에 따라 결과가 달라진다.**
`lock01`은 잠금 시험만 쓴다.

### 여기 없는 것

| 무엇 | 왜 |
|---|---|
| `clinic_id` | 다중 의원 격리가 아직 모델에 없다. 한 의원 기준이다 |
| 잠금된 상태 자체 | Redis에 있지 DB에 없다. **시험이 5번 틀려서 만든다** |
| `password_hash` | 시드가 `SEED_STAFF_PASSWORD`로 만든다 |

## 10. 앞뒤가 맞아야 하는 것 — 어기면 화면이 거짓말을 한다

**날짜 하나에서 나머지가 따라 나온다.** 진료일을 옮기면 아래가 전부 따라 움직여야 한다.

| 규칙 | 어기면 |
|---|---|
| `소진예정일 = 진료일 + 처방일수` | 소진 임박 목록이 엉뚱한 사람을 부른다 |
| `총투원문 × 단위 = 처방일수` — 통수면 `× 28` | 84일이 3일이 된다 (`SYN-PCOS-02`) |
| 확인 문자는 **그 회차가 지난 방문에만** 있다 | 아직 안 보낸 문자를 보냈다고 한다 |
| 회차는 `발송 완료` · `보완` · `계획된 중단`에만 있다 | **「계획」과 「보냄」이 섞인다.** 승인 대기 상태의 `D+7`은 예정이지 발송이 아니다 |
| `문자수신동의 = N`이면 회차가 없다 | 거부한 사람에게 보낸 기록이 남는다 |
| 열람 여부는 **보낸 뒤에만** 있다 | 안 보낸 문자를 읽었다고 한다 |
| `계획된 중단`은 이탈 표시가 **없다** | 의사가 멈춘 처방을 시스템이 이탈로 부른다 |
| `소진 후 7일 경과`는 실제로 7일이 지난 뒤에만 | 이탈 판정을 못 믿게 된다 |
| 진료일은 **일요일이 아니다** | 의원이 안 여는 날에 진료가 있다 |

> 처음 만든 20행이 이 규칙을 **14군데 어기고 있었다.** 8월 중순 진료에 `D+15` · `D+30` 회차가 적혀 있었다 — 아직 오지도 않은 문자다.
> 눈으로는 안 보인다. **검사로 잡았다.** `KEY-14` 시드 스크립트는 적재 후 같은 검사를 돌려야 한다.

### 계획된 중단은 「조건이 걸리는데도 안 뜨는」 행이어야 한다

`SYN-EMS-03`은 소진 후 13일이 지났다. 즉 **이탈 조건이 실제로 충족된다.** 그런데도 표시가 뜨면 안 된다.
조건이 아예 안 걸리는 행으로 만들면 오판 검사가 되지 않는다 — 안 걸리니 안 뜨는 것뿐이다.

## 11. 적재 규칙 (`KEY-14`에 넘기는 것)

| | |
|---|---|
| 고정 시드 | 같은 명령이 **같은 결과**를 낸다. uuid는 시나리오 ID에서 결정적으로 만든다 |
| 선택 적재 | `빈 상태` · `정상만` · `전체`를 골라 넣을 수 있다 — `S1-1`을 보려면 아무것도 안 넣는다 |
| 중복 처리 | 다시 돌려도 쌓이지 않는다. **재실행 시 직원·환자의 모든 필드를 실제로 갱신한다** — CSV를 고친 뒤 재실행하면 DB에 반영된다 |
| CSV 검증 | `all_staff()` 픽스처를 통해 `must_change_password`·`status`·병원 레이블 오류를 DB 쓰기 전에 검증한다. 오류 시 즉시 중단한다 |
| 담당의 검증 | 담당의 이름이 H1 직원 목록과 맞지 않으면 `stderr` 경고를 출력하고 `doctor_id=None`으로 저장한다 |
| 데모 ≠ 테스트 | 데모용은 `SYN-EMS-01` · `SYN-PCOS-01` 둘이면 충분하다. 예외 케이스는 테스트에서만 |
| 발송 금지 | **적재된 번호로 실제 문자를 보내지 않는다.** 개발·테스트 환경은 콘솔 출력으로 대체 |
